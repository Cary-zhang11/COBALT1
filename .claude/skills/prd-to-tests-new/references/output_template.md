# 输出文档模板

## 输出位置与命名规则

### 输出目录规则

所有生成的文件统一输出到以下目录结构：

```
{项目根目录}/docs/{需求名称}_{YYYYMMDD}\

```

- `{技能目录}`：本技能 `SKILL.md` 所在目录
- `{项目根目录}`：`{技能目录}/../../../`（向上 3 级，即 `.claude` 的父目录）
- `{需求名称}`：取 PRD 文件名（不含 `.docx` 扩展名）
- `{YYYYMMDD}`：生成日期，格式为 8 位数字

示例：
- PRD 文件：`详情页PK功能改版.docx`
- 生成日期：2026-04-29
- 技能目录：`/path/to/.claude/skills/prd-to-tests-new`
- 项目根目录：`/path/to`
- 输出目录：`/path/to/docs/详情页PK功能改版_20260429\`

### 目录下文件清单

该目录下包含以下文件：

| 文件/目录 | 说明 |
|-----------|------|
| `{需求名称}_source.md` | docx2text.py 转换后的带样式 Markdown（中间产物） |
| `{需求名称}_images/` | 提取的 PRD 内嵌图片（中间产物） |
| `{需求名称}_测试用例.md` | 最终输出的测试用例文档 |

### 测试用例文件命名规则

测试用例文件命名格式：`{PRD文件名}_测试用例.md`

示例：
- PRD 文件：`详情页PK功能改版.docx`
- 测试用例文件名：`详情页PK功能改版_测试用例.md`

## 冒烟清单选取规则

冒烟清单包含以下优先级的所有用例：
- 全部 P0（核心阻断）
- 全部 P1（重要功能）
- 全部 P2（次要功能）
- 全部 P3（体验优化）
- 全部兼容性用例（无论优先级）

即：所有用例都纳入冒烟清单。冒烟清单与回归测试清单一致。

## 完整性自检清单

生成文档后，必须逐项执行以下检查：

### 编号检查
- [ ] 所有用例编号格式为 tc-XXX-pY（三位数字+单字符优先级）
- [ ] 用例编号无重复
- [ ] 用例编号连续无跳跃（如从 tc-003-p0 直接到 tc-005-p0）

### 字段检查
- [ ] 用例行包含编号和优先级（tc-001-p0）
- [ ] 每条用例都包含条件+动作行和预期结果
- [ ] 所有字段值非空

### 原子性检查
- [ ] 预期结果逐条展开为独立子节点，无多个校验条件合并
- [ ] 预期结果与测试步骤逻辑对应

### 覆盖度检查
- [ ] 每个功能点至少有一条用例
- [ ] P0 功能点覆盖了 D1-D5 维度
- [ ] P1 功能点覆盖了 D1-D4 维度

### 需求覆盖检查
- [ ] 需求提取清单中每条需求均已映射到用例或待澄清问题
- [ ] 需求覆盖对照表中无状态为 `✗` 的行

### 参数一致性检查
- [ ] 同模块内相同参数（实验参数、pvareaid、tag 号等）的格式和数值在所有用例中保持一致
- [ ] AB 实验各方案的参数值互不冲突

### 术语一致性检查
- [ ] 同一概念在整篇文档中使用统一术语
- [ ] PRD 中的字段名、状态值、角色名在用例中保持一致

### 来源标注检查
- [ ] 主动补充的用例已标注 `【主动补充】`
- [ ] 未标注来源的用例默认为 PRD原文

### 重复检查
- [ ] 无两条用例具有相同的条件+动作和相同的预期结果

### 格式检查
- [ ] 输出文档中无 Markdown 表格（`| xxx |` 格式），全部改用列表
- [ ] 需求覆盖对照表使用列表格式
- [ ] 校验链模块第一条用例为汇总用例，描述完整校验顺序

### 模块分组检查
- [ ] 模块划分符合 PRD 表格行规则
- [ ] 场景分组命名清晰，反映操作场景
- [ ] 校验链模块按环节分组，每个环节包含正常/分支/异常用例
- [ ] 校验链模块第一个环节上方有汇总用例

### 章节完整性检查
- [ ] PRD 中每个章节标题均已映射到用例、合并描述、元数据或待澄清问题
- [ ] 无表格章节（如实验计划、参数说明）不可仅在对照表中一笔带过，需生成独立用例或合并描述
- [ ] 含图片但无表格的章节，图片内容已纳入用例
