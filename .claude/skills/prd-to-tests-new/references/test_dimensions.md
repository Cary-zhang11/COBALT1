# 测试维度详解

## 维度分类

### D1: 主流程（Happy Path）

用户按预期操作，输入正常数据，系统给出预期结果。

**覆盖范围：**
- 核心业务流程的完整生命周期：创建 → 处理 → 完成 / 归档
- 用户最常见的操作路径
- 状态机的每个正常状态转换

**编写要求：**
- 每条用例覆盖一个具体的用户操作场景
- 优先覆盖 P0 和 P1 功能
- 步骤描述清晰可执行，预期结果可判定

---

### D2: 分支流程

同一功能点的不同操作路径。

**覆盖范围：**
- 可选步骤的启用 / 跳过
- 条件分支的不同走向（如审批通过 vs 审批驳回）
- 不同用户角色的操作差异
- 不同输入数据导致的不同处理结果
- 批量操作与单条操作的差异

**拆分规则：**
- 优先按输入条件拆分，不同输入条件导致不同结果的各一条用例
- 其次按操作路径拆分，不同操作路径各一条用例
- 操作步骤相同但预期结果不同的，可合并为一条，预期结果分分支列出

---

### D3: 异常与容错

系统遇到非正常输入或非预期操作时的行为。

**输入异常：**
- 必填字段为空
- 字段超长 / 超短
- 非法字符 / 特殊字符注入（XSS 测试）
- 错误的数据类型
- 重复提交
- 格式不匹配（如日期格式错误、邮箱格式错误）

**操作异常：**
- 网络中断
- 超时
- 并发操作冲突
- 权限在执行过程中被收回

**数据异常：**
- 关联数据已被删除
- 关联数据状态不允许操作
- 数据一致性被破坏
- 空数据 / 零数据场景

**拆分规则：**
- 每种异常类型各一条用例
- 操作步骤相同但异常类型不同的，可合并为一条

---

### D4: 边界条件

数值、数量、时间、长度的边界测试。

**数值边界：**
- 最小值、最大值
- 最小值 -1、最大值 +1
- 零值、负数

**数量边界：**
- 空列表（0 条）
- 单条记录
- 上限数量
- 超限数量

**时间边界：**
- 跨天、跨月、跨年
- 闰年 2 月 29 日
- 时区切换
- 生效时间 / 失效时间临界点

**长度边界：**
- 空字符串
- 最小长度
- 最大长度
- 最大长度 +1

**编写要求：**
- 每个边界值单独一条用例，不设上限
- 边界 ±1 必须覆盖
- 等价类（如各种正常范围内的值）合并为一条用例

---

### D5: 权限与安全

越权访问和数据安全测试。

**覆盖范围：**
- 未登录状态访问受保护资源
- 低权限角色尝试高权限操作（垂直越权）
- 同级用户间的数据隔离（水平越权：用户 A 操作用户 B 的数据）
- 敏感数据脱敏展示（手机号、身份证号、银行卡号等）
- SQL 注入测试
- XSS 输入过滤测试
- 接口级别权限校验（不仅测试 UI 层）

---

### D6: 兼容性

跨平台、浏览器、设备、版本兼容测试。

**覆盖范围：**
- **App 端**：iOS / Android 主流版本、不同屏幕尺寸
- **Web 端**：Chrome / Safari / Firefox / Edge 最新两个版本
- **API**：向后兼容老版本接口
- **数据**：旧数据格式迁移、历史数据兼容
- **国际化**：多语言切换、多时区、多货币（如 PRD 涉及）

**注意：** 兼容性作为单独大模块，覆盖所有功能点的兼容性场景，不按功能点分散。

---

### D7: 性能

仅当 PRD 中明确提到性能指标时生成。

**覆盖范围（仅 PRD 有对应要求时）：**
- 页面加载时间
- 接口响应时间
- 大数据量列表渲染
- 批量操作耗时
- 并发用户场景

**编写要求：**
- 如果 PRD 没有提到性能指标（如响应时间、并发数），则不生成性能用例
- 如果 PRD 有提到，按 PRD 中的具体指标编写用例

---

### D8: 状态流转

对有状态实体的功能点，覆盖状态机的所有转换。

**覆盖范围：**
- 每个状态的合法前驱状态
- 每个状态的合法后继状态
- 非法状态转换的拦截
- 状态转换的触发条件和副作用

**拆分规则：**
- 每个合法状态转换各一条用例
- 非法状态转换各一条异常用例
- 操作步骤相同但目标状态不同的，可合并为一条，预期结果分分支列出

---

### D9: 第三方交互

APP 与外部应用、SDK、H5 页面的跳转、唤起、返回行为。

**覆盖范围：**
- 跳转第三方应用（地图导航、易签宝签约、天天拍检测报告）
- 唤起系统能力（复制粘贴板、分享面板、相机相册）
- 跳转 H5 页面（客服咨询页、活动页）
- 从第三方返回 APP 后的状态刷新

**编写要求：**
- 覆盖正常跳转/唤起、参数传递正确、返回后状态刷新
- 覆盖第三方应用未安装、跳转失败、返回异常等容错场景
- 纯 H5 内页面跳转（同域名路由）归入 D2 分支流程，不触发 D9

---

### D10: 数据展示边界

接口返回异常数据时，页面的兜底展示和容错处理。

**覆盖范围：**
- 空态数据（null、undefined、空字符串、空数组）
- 超长数据（文案超长、地址超长、名称超长）
- 异常数据格式（数字变字符串、日期格式错误）
- 关联数据缺失（依赖的接口返回失败或空）

**编写要求：**
- 仅针对 PRD 中明确有数据来源的展示字段
- 纯静态文案（无接口数据）不触发本维度
- 页面不崩溃、不白屏，兜底展示合理
- 异常字段不影响其他正常字段的展示

---

### D11: 关键分支（顺序）

多条件互斥时的优先级判断和降级逻辑。

**覆盖范围：**
- "优先 A，如没有则 B" 类顺序逻辑
- "若 X 则 Y，反之则 Z" 类条件分支（复杂场景）
- 状态/权限决定 UI 可用性（按钮亮起/置灰）
- 多来源取值时的优先级（如缓存 > 接口 > 默认值）

**编写要求：**
- 简单二选一（勾选/未勾选、有/无）归入 D2 分支流程，不单独触发 D11
- 涉及 3 个及以上条件层级，或存在明确优先级/降级路径时触发
- 每条用例聚焦一个条件路径，预期结果明确不执行其他路径

---

### D12: 触区与机型

按钮热区、边缘点击、屏幕适配。

**覆盖范围：**
- 按钮/可点击元素的边缘触区响应
- 横竖屏切换后的布局自适应
- 不同分辨率/屏幕尺寸的适配
- 刘海屏、全面屏、小屏设备的特殊处理
- 长文案的截断、换行、最大行数限制

**编写要求：**
- 纯展示页面无交互元素 → 不触发
- 与 D6 兼容性合并为独立大模块，不按功能点分散
- 机型适配作为 P2/P3 用例，不在 P0 中出现

---

## 维度裁剪规则

不是每个功能点都需要覆盖全部 12 个维度。按以下两层规则裁剪：

### 第一层：触发判定（按需求信号）

| 维度 | 触发信号 | 不触发判定 |
|------|---------|-----------|
| D5 权限安全 | PRD 出现登录态/角色/权限相关描述 | 仅埋点参数区分登录态（如 type=0/1）→ 不触发 |
| D7 性能 | PRD 出现加载时间/响应时间/并发指标 | PRD 未提及任何性能指标 → 不触发 |
| D9 第三方交互 | PRD 出现跳转/唤起外部应用 | 纯 H5 内跳转（页面间路由）→ 不触发，归入 D2 |
| D10 数据展示边界 | PRD 出现"展示 xx"且有数据来源说明 | 纯静态文案（无数据接口）→ 不触发 |
| D11 关键分支 | PRD 出现"优先"、"如没有则"、"反之"等多条件描述 | 简单二选一（勾选/未勾选）→ 归入 D2，不单独触发 |
| D12 触区与机型 | PRD 出现可点击元素或适配要求 | 纯展示页面无交互 → 不触发 |

### 第二层：优先级裁剪（按功能重要性）

| 功能优先级 | 必须覆盖的维度 | 可选维度 |
|-----------|--------------|---------|
| P0（核心阻断） | D1, D2, D3, D11 | D4, D8, D9, D10 |
| P1（重要功能） | D1, D2, D3 | D4, D8, D9, D10, D11 |
| P2（次要功能） | D1, D2, D3 | D4, D11 |
| P3（体验优化） | D1, D3 | — |

**特殊规则：**
- 兼容性（D6）和触区与机型（D12）统一放在单独的兼容性大模块中，不按功能点分散
- 埋点统一放在单独的埋点大模块中，不按功能点分散
- 性能（D7）仅在 PRD 提到时生成，否则跳过
- AB 实验中未单独描述的模块需验证：当某个方案未描述某个模块时，需判断是隐式继承其他方案、该模块隐藏、还是需求遗漏，不可直接跳过。如有歧义，生成用例的同时记入待澄清问题。
