# Step 1: 输入解析与需求分析

## 目标
将 PRD 文档转换为可分析的文本，并提取关键信息。

## 必须输出清单

执行本步骤前，必须逐项声明：

- [ ] 已读取 PRD 原文（或 docx 转换后的 Markdown）
- [ ] 已识别文档结构（章节层级、表格、列表）
- [ ] 已提取所有功能模块列表
- [ ] 已提取所有业务流程 / 用户故事
- [ ] 已识别数据模型和字段定义
- [ ] 已识别权限角色定义
- [ ] 已识别非功能需求（性能、安全、兼容性等）
- [ ] 已标记模糊或不确定的需求点

## 执行步骤

### 1.1 文档转换

若输入为 `.docx` 文件，使用技能目录下的 `scripts/docx2text.py` 将其转为 Markdown：

```bash
python scripts/docx2text.py <docx文件路径>
```

转换后读取生成的 Markdown 文件进行分析。

### 1.2 结构识别

理解 PRD 的层级结构：
- **一级章节**：通常是功能模块或业务领域
- **二级/三级章节**：具体功能点
- **表格**：字段定义、状态机、枚举值、规则矩阵
- **流程图描述**：业务流程、审批流、状态流转
- **附录**：术语表、全局规则

### 1.3 关键信息提取

从 PRD 中提取以下信息，形成结构化摘要：

#### 功能模块清单
列出所有功能模块，标注模块间的依赖关系。

#### 业务流程摘要
每个业务流程用简短的步骤描述，标注入口和出口。

#### 数据模型
- 涉及的实体 / 表
- 关键字段及约束（类型、长度、必填、默认值、枚举值）
- 实体间关系

#### 权限与角色
列出所有角色及其操作权限矩阵。

#### 全局规则
- 命名规则
- 编号规则
- 计算公式
- 时间 / 时区规则
- 国际化 / 多语言要求

### 1.4 歧义与待澄清

标记以下类型的问题：

- **矛盾定义**：同一概念在不同章节有冲突的描述
- **缺失信息**：缺少必要字段定义、状态转换条件、异常处理规则
- **模糊描述**：使用"可能""大概""适当"等不确定词语的地方
- **隐含假设**：未明确说明但对测试至关重要的前提条件

这些问题最终会汇总到三方分析报告的「问题汇总」章节，作为后续冒烟用例生成的输入。
