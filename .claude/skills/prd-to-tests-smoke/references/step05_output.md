# Step 5: 输出格式与完整性校验

## 目标
将三方分析报告和开发冒烟用例整理为规范的 Markdown 文档，并进行完整性校验。

## 必须输出清单

执行本步骤前，必须逐项声明：

- [ ] 三方分析报告已生成，包含三个视角的独立分析、红蓝对抗、结论汇总
- [ ] 冒烟用例文档已生成，所有 P0 功能点均有对应用例
- [ ] 用例编号无重复，格式统一为 `SMK-{模块}-{序号}`
- [ ] 每条用例的模板字段齐全（编号、模块、标题、优先级、前置条件、步骤、预期结果）
- [ ] 预期结果已原子化（无多个校验条件合并在一条中）
- [ ] 三方分析中的关键风险均有对应冒烟用例覆盖
- [ ] 文档结构符合本节定义的模板

## 输出文档结构

本步骤产出两份文档：三方分析报告和开发冒烟用例。

```markdown

{明确各功能边界，标注模糊地带}

## 二、架构师分析

{数据流向、状态管理、技术选型}

{缺失接口、参数不完整、错误码缺失}

{技术实现层面的优化建议}

### 5.3 产品建议
{需求完善和边界补充建议}

### 5.4 测试重点
{后续测试必须重点关注的方向}

### 5.5 冒烟测试范围建议
{建议纳入冒烟测试的核心功能点}
```

## 完整性校验

### 三方分析报告校验

生成报告后，执行以下检查：
- [ ] 三个角色（产品/架构/测试）均有独立分析内容
- [ ] 红蓝对抗环节至少发现 3 个具体问题
- [ ] 每个问题都具体到 PRD 的某个章节或功能点
- [ ] 结论汇总中包含「冒烟测试范围建议」
- [ ] 术语与 PRD 保持一致

### 冒烟用例文档校验

生成文档后，执行以下检查：

#### 编号检查
- 无重复编号
- 编号格式统一为 `SMK-{模块}-{序号}`

#### 字段检查
遍历每条用例，确认以下字段均存在且非空：
- 所属模块
- 功能点
- 前置条件
- 测试步骤
- 预期结果
- 三方关联

#### 数量与步骤检查
- 用例总数在 5-20 条之间
- 每条用例步骤不超过 5 步
- 所有用例优先级均为 P0

#### 覆盖度检查
- 每个 P0 功能点至少有一条冒烟用例
- 三方分析中的关键风险均有对应冒烟用例
- 若某 P0 功能点用例数为 0，说明漏生成，需返回 Step 4 补充

#### 原子性检查
扫描所有预期结果，若发现多个独立校验条件合并在一起，拆分为独立子项。

### 双文档一致性检查
- 冒烟用例中的「三方关联」字段必须能在三方分析报告中找到对应内容
- 两份文档中的项目名称、版本号、日期保持一致
