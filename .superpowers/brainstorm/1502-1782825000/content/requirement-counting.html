"需求数" 统计算法方案

同样的 PRD 文档可能生成多次用例，如何定义"一个需求"？

数据源参考

字段 含义 示例
inputFiles上传的原始文档路径列表["uploads/1780581436572-卖车页面改版.docx"]
inputPRD 完整文本（由文档解析而来）"# 卖车页面改版\n## 功能概述\n..."
businessType业务类型标签"二手车" / "新车"
A

按 input 文本 MD5 去重

对 input 字段取 MD5，相同哈希值 = 同一个需求。同一份文档多次上传，只要内容一致就算 1 个需求。

B

按上传文件名去重

对 inputFiles 中的文件名（去路径和上传时间戳前缀）做归一化后去重。如 "卖车页面改版.docx" 多次上传算 1 个需求。

C

按 input 前 200 字相似度去重

取 input 前 200 字符做哈希，同一份 PRD 即使有小修改，开头通常不变，仍识别为同一需求。

我的推荐

推荐方案 A（input MD5 去重）：
  • 语义最准确 — 内容相同就是同一个需求，不受文件名变化影响
  • 实现简单 — 后端对 input 做 MD5 后 groupBy 即可
  • PRD 内容即使有微小修改也会被正确识别为新需求（符合实际）
  • 不依赖用户是否上传文件（input 字段始终有值）

两个指标定义（确认后敲定）

指标 统计口径 SQL 思路
任务数/周 时间窗口内完成的 task 数量 COUNT(task) WHERE status IN ('completed','paused') AND createdAt IN [window]
需求数/周 时间窗口内去重后的 PRD 文档数 COUNT(DISTINCT MD5(input)) WHERE status IN ('completed','paused') AND createdAt IN [window]
