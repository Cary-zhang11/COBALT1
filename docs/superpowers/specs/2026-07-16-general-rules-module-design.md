# 通用规则模块设计

## 背景

用例生成向导 Step 2 允许用户勾选知识库中的业务文档作为参考。当前机制存在两个缺口：

1. **输出层缺口**：知识库文档内容在生成的用例文档中无独立展示位置，评审者无法直接看到本次生成参考了哪些业务规则
2. **SKILL 规则层缺口**：`SKILL.md` 和 `generation_rules.md` 没有显式约束 AI 如何将知识库规则应用到用例中，规则可能被忽略或溶解

## 目标

1. 在输出文档中新增"通用规则"模块，原样展示 Step 2 勾选的知识库文档内容，供评审追溯
2. 在 SKILL 规则层加强约束，确保知识库中明确写到的业务规则在用例中体现

## 改动范围

仅修改 3 个 SKILL 规则文件，不涉及前端/后端代码改动：

| 文件 | 改动 |
|------|------|
| `output_template.md` | 新增"二、通用规则"章节模板 + 编号顺延 |
| `generation_rules.md` | 新增"知识库参考规则"一节 |
| `SKILL.md` | Step 0/4/6/7 各追加知识库相关指令 + 规则对应表更新 |

## 设计详情

### 一、输出结构变更（output_template.md）

文档结构调整为：

```
一、测试用例              ← 不变
二、通用规则              ← 新增（原样展示 knowledge/ 文档内容）
三、网络相关              ← 原二，编号顺延
四、兼容性测试            ← 原三
五、埋点测试（如有）      ← 原四
六、完整性检查报告        ← 原五
```

**"二、通用规则"模块格式规则：**

- 使用 `## 二、通用规则` 作为模块标题
- 每个知识文档作为 `### 2.{N} {文档标题}` 子模块
- 文档内容必须转为**标题 + 列表结构**（兼容 `md2xmind.py` 转换）：
  - 原文中的章节标题 → 保留为 `####` 或更深标题
  - 原文中的普通段落 → 转为 `- ` 列表项
  - 原文中的表格 → 转为列表格式（与现有规则一致：禁止 markdown 表格）
- 若用户未勾选任何知识库文档 → **跳过此模块**，不输出空章节，后续模块编号回退（网络相关仍为二）
- **完整性检查报告排除**：该模块不包含测试用例，不出现在完整性检查报告的「用例数量统计」表中，也不参与优先级统计和维度覆盖检查

**示例输出：**

```markdown
## 二、通用规则

> 本模块展示本次生成参考的业务知识文档内容，供评审追溯。

### 2.1 卖车页面通用业务规则

#### 登录态规则
- 所有页面入口需校验登录态
- 未登录时跳转登录页，登录后返回原页面

#### 协议校验规则
- 提交前必须勾选用户协议
- 未勾选时弹出协议选择弹层，拦截提交

### 2.2 支付安全规范

#### 支付参数校验
- 金额必须大于 0
- 支付方式至少支持一种
```

**XMind 转换效果：**

```
二、通用规则
├── 2.1 卖车页面通用业务规则
│   ├── 登录态规则
│   │   ├── 所有页面入口需校验登录态
│   │   └── 未登录时跳转登录页...
│   └── 协议校验规则
│       ├── 提交前必须勾选用户协议
│       └── 未勾选时弹出协议选择弹层...
└── 2.2 支付安全规范
    └── 支付参数校验
        ├── 金额必须大于 0
        └── 支付方式至少支持一种
```

### 二、知识库参考规则（generation_rules.md）

新增一节"知识库参考规则"：

**适用范围：** 当工作目录中存在 `knowledge/` 子目录且包含文件时，本规则生效。

**三条强制要求：**

| 要求 | 说明 |
|------|------|
| **读取并提取** | 逐一读取 `knowledge/` 目录下所有文件，提取业务规则、术语定义、流程约束、校验逻辑 |
| **必须在用例中体现** | 知识库文档中明确写到的业务规则，必须在对应功能模块的用例中体现（作为前置条件、测试步骤或预期结果） |
| **冲突以 PRD 为准** | 知识库规则与 PRD 描述冲突时，以 PRD 为准，同时在完整性检查报告的「PRD 自身矛盾检测」中记录冲突点 |

**"对应功能模块"判定规则：**

- 知识库规则明确指向某功能模块（如"提交前必须勾选协议"）→ 归入该模块用例
- 知识库规则为跨模块通用约束（如"所有页面需校验登录态"）→ 归入所有相关模块用例
- 知识库规则在 PRD 中无对应功能点 → 不单独生成用例（仅放入"通用规则"模块展示）

**与"通用规则"模块的关系：**

- "通用规则"模块：原样展示文档内容，保证可见性
- SKILL 约束：确保规则被实际应用到用例生成中，保证执行力
- 两者互补

### 三、SKILL.md 指令补充

在现有步骤中追加知识库相关指令（不改变步骤编号）：

**Step 0（规则预加载）追加：**

> 若工作目录中存在 `knowledge/` 子目录，必须逐一读取其中所有文件，提取业务规则、术语定义、流程约束，作为后续步骤的输入。

**Step 4（模块划分与场景分组）追加：**

> **知识库规则映射**：将 `knowledge/` 文档中提取的业务规则，映射到对应的功能模块。规则明确指向某模块的归入该模块；跨模块通用约束归入所有相关模块。映射结果在需求提取清单中标注来源。

**Step 6（全量用例生成）追加：**

> **知识库规则体现**：知识库文档中明确写到的业务规则，必须在对应模块用例中体现（作为前置条件、测试步骤或预期结果）。若知识库规则与 PRD 冲突，以 PRD 为准，同时记入待澄清问题。

**Step 7（输出与校验）追加：**

> **通用规则模块**：若用户勾选了知识库文档（工作目录存在 `knowledge/` 子目录且非空），在"一、测试用例"之后输出"二、通用规则"模块，原样展示各文档内容（转为标题 + 列表结构，兼容 XMind 转换）。后续模块编号顺延。若无知识库文档，跳过此模块。

**规则章节对应表更新：**

| 步骤 | 用到的规则文件 |
|------|---------------|
| Step 0 预加载 | `references/*` + `knowledge/` 目录（如有） |
| Step 4 知识库映射 | `generation_rules.md` → 知识库参考规则 |
| Step 6 知识库体现 | `generation_rules.md` → 知识库参考规则 |
| Step 7 通用规则输出 | `output_template.md` → 通用规则模块模板 |

## 条件触发机制

所有知识库相关行为均为条件触发，判断条件为：工作目录中是否存在 `knowledge/` 子目录且包含文件。

| 场景 | 行为 |
|------|------|
| 用户未勾选知识库 → `knowledge/` 不存在 | 跳过所有知识库相关步骤，不输出"通用规则"模块，编号回退 |
| 用户勾选知识库 → `knowledge/` 有文件 | 读取 → 映射 → 体现 → 输出"通用规则"模块 |

前端侧无需改动：`generate-wizard.tsx` 仅在 `selectedKnowledgeIds.size > 0` 时追加提示注入，不选则不注入。双重保险：条件指令 + 条件提示，不会误触发。
