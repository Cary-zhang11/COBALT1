```markdown

---

## 知识库参考规则

### 适用范围

当工作目录中存在 `knowledge/` 子目录且包含文件时，本规则生效。若无该目录或目录为空，本规则全部跳过。

### 三条强制要求

| 要求 | 说明 |
|-----|------|
| **读取并提取** | 逐一读取 `knowledge/` 目录下所有文件，提取业务规则、术语定义、流程约束、校验逻辑 |
| **必须在用例中体现** | 知识库文档中明确写到的业务规则，必须在对应功能模块的用例中体现（作为前置条件、测试步骤或预期结果） |
| **冲突以 PRD 为准** | 知识库规则与 PRD 描述冲突时，以 PRD 为准，同时在完整性检查报告的「PRD 自身矛盾检测」中记录冲突点 |

### 对应功能模块判定规则

- 知识库规则明确指向某功能模块（如"提交前必须勾选协议"）→ 归入该模块用例
- 知识库规则为跨模块通用约束（如"所有页面需校验登录态"）→ 归入所有相关模块用例
- 知识库规则在 PRD 中无对应功能点 → 不单独生成用例（仅放入"通用规则"模块展示）

### 与"通用规则"模块的关系

- **"通用规则"模块**（`output_template.md` → 二、通用规则）：原样展示知识库文档内容，供评审追溯，保证可见性
- **本规则**：确保知识库中的业务规则被实际应用到用例生成中，保证执行力
- 两者互补：前者展示"参考了什么"，后者确保"用上了什么"

### 输出格式约束

"通用规则"模块内容必须使用标题 + 列表结构（兼容 `md2xmind.py` 转换）：
- 原文中的章节标题 → 保留为 `####` 或更深标题
- 原文中的普通段落 → 转为 `- ` 列表项
- 原文中的表格 → 转为列表格式（禁止 Markdown 表格）
- 每个知识文档作为 `### 2.{N} {文档标题}` 子模块

### 统计排除

"通用规则"模块不包含测试用例，不纳入完整性检查报告的：
- 用例数量统计表
- 优先级统计表
- 维度覆盖检查
```
